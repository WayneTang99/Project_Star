# IMPLEMENTATION_PLAN.md
Project_Star 实现计划。与 `AGENTS.md`（导航）、`docs/ARCHITECTURE.md`（架构）配合使用；术语定义见 `docs/GLOSSARY.md`。

## 实施约定

- 实现分 7 步（地基属性实体 → 通用机制 → 全局层 → 对局层 → 战斗层 → 三层串联 → 表现层 UI），自底向上推进。
- **逐步确认**：任何计划都分步推进。**每步实施前必须先向用户确认**，该步逻辑完全理解、疑问清零、形成闭环后方可进入实现。
- **主动提问**：遇到不理解的点必须提出讨论，不猜测推进。
- **架构建议**：若对现有架构有更好的建议，须主动提出，供用户决策。
- **不擅自执行后续步骤**：每一步完成并确认后，才进入下一步。
- **每步完成标准**：`dotnet build` 通过；纯逻辑部分配单元测试（价值公式 / 推挤算法 / Resolver）。
- 目录结构：Core / Systems / Match / Combat / Entities / UI。
- 能力复用约定：能力必须可复用，禁止为单张卡写专属能力；卡牌组合已有能力。
- 词条不进入代码逻辑，仅作需求语义概念。

## 实现步骤

### 第 1 步：地基——属性与实体

- 状态容器：对局资源 AttributeSet + 战斗状态 BattleState，ApplyModifier / RemoveModifier。
- 实体基类 `HeroBase` / `CardBase` / `EncounterBase`（身份字段 get-only，key 用 StringName）。
- 反射模板池 `PoolBase<T>`。
- **完成标准**：`dotnet build` 通过。

- ✅ **2.2 能力与效果基类**：`IAbility` + `AbilityBase`（主动/被动区分，能力只负责执行逻辑）、`IEffect` + `EffectBase`（即时/周期分类）；遵循开闭原则设计，扩展点预留完整。

### 第 3 步：全局层——管理器 + 卡牌经济

#### 第 3 步子拆解（逐步讨论+执行）

- [ ] **3.1 标签系统**：标签容器（`HashSet<StringName>`）、标签常量（`Small`/`Medium`/`Large`/`Weapon`/`Clothing`/`Human`/`Mechanical`/`Vehicle`/`Consumable`）、显示名映射（未知标签返回原始 key）、型号标签由尺寸自动推导。
- [ ] **3.2 卡牌价值公式**：价值系数 × 等级 × 型号系数（小 1 / 中 2 / 大 3），特殊价值物品子类覆写系数（如兽皮系数 4）；初始价值计算、获得折半（初始价值 × 0.5）、购买全额计价、出售按现值回补。
- [ ] **3.3 具体英雄子类**：非抽象 `HeroBase` 子类（构造函数注入身份字段 key/展示名/阵营 + 覆写初始属性差异），如 `TemplateHero`，供模板池反射收集。
- [ ] **3.4 具体卡牌子类**：非抽象 `CardBase` 子类（构造函数注入身份字段 key/展示名/归属/尺寸 + 组装能力），如 `ShockPistolCard`，供模板池反射收集。
- [ ] **3.5 HeroManager**：反射模板池收集英雄子类、从模板复制独立实例、玩家当前英雄。
- [ ] **3.6 CardManager**：反射模板池收集卡牌子类、实例化、玩家卡池（PlayerCards）、按归属 key 过滤供商店。
- **完成标准**：`dotnet build` 通过；价值公式配单元测试。

### 第 4 步：对局层——棋盘 + 轮次事件

#### 第 4 步子拆解（逐步讨论+执行）

- [ ] **4.1 推挤算法**：纯函数（评估 `PushEvaluator` / 执行 `PushExecutor` 分离）、无阻挡直落 / 有阻挡模拟左右择优、择优规则（距离短 → 影响少 → 取 Right）、返回方向与结果。
- [ ] **4.2 GameBoard 纯数据**：卡牌引用 + 顺序（Order）+ 占用格（StartCell），不存渲染坐标；战场 + 备战各 10 格；`GetCards()` / `GetLayout()` 等查询。
- [ ] **4.3 BoardManager**：双棋盘管理（战场 + 备战）、放置 / 移除 / 交换 / 跨区拖拽编排、预览（评估）与提交（执行）分离、随对局创建 / 销毁。
- [ ] **4.4 轮次调度**：8 回合 / 轮、当前轮 / 当前回合推进、`IsPvPTurn`（第 8 回合）、`CompleteTurn`、`CheckDefeat`。
- [ ] **4.5 遭遇排程**：默认三选一（≥1 商店）、第 4 回合三怪物、第 8 回合 PvP；按 MinRound / MaxRound 过滤模板；未出现加成（基础权重 × 倍率）、按 key 跟踪已出现、新对局清空。
- [ ] **4.6 遭遇执行与商店交易**：遭遇点击进入战斗 / 商店交易（买卡扣钱入池、卖卡出池回钱）、`ItemPurchasedEvent` / `ItemSoldEvent`、归属 key 过滤卡池。
- **完成标准**：`dotnet build` 通过；推挤算法配单元测试。

### 第 5 步：战斗层——时钟 + 解析器

#### 第 5 步子拆解（逐步讨论+执行）

- [ ] **5.1 BattleClock 两层帧推进**：时间推进层（高频，只推进时钟）+ 逻辑结算层（低频，做逻辑结算）；约束：逻辑相关步长为逻辑步长的整数倍；两层可独立暂停、步长可配置。
- [ ] **5.2 逻辑步序**：8 步序（坍缩检查 → 寂灭检查 → 卡牌 CD 递减 → 主动能力入队 → 英雄状态结算 → 处理能力队列 → 检查死亡 → 检查战斗结束）。
- [ ] **5.3 能力队列与触发**：主动（CD 到 → 进队列 depth=0）与被动（事件触发 → 进队列 depth=上一层+1）；深度上限（可配置，默认 ≤3）；CanActivate 检查（含能量检查）；同一步内按入队顺序处理，处理完再查死亡。
- [ ] **5.4 状态周期结算**：辐射（1s 周期 / 1s 衰减、伤害 Floor、无视护甲）、腐蚀（1s / 0.2s、优先扣护甲）、生命再生（1s 回血）、能量再生（1s 回能、上限 MaxEnergy）、超频 ×2 / 麻痹 ×0.5 / 禁锢停止 / 两者抵消 ×1。
- [ ] **5.5 坍缩 / 寂灭**：坍缩时间后双方同时扣血（按配置曲线：斐波那契 / 线性 / 分段）、寂灭时间强制结束判玩家胜。
- [ ] **5.6 战斗生命周期与 BattleResult**：派生初始值 → 主循环 → 收集永久变化（永久摧毁 = 从玩家卡池删除）→ 丢弃临时状态 → 返回结果；结束条件（敌方死 / 己方死 / 双方死判胜 / 寂灭）、结束原因（EnemyHeroDied / PlayerHeroDied / Timeout / Surrender / Draw）。
- [ ] **5.7 战斗内事件**：具体事件类（BattleStartEvent / TickEvent / AbilityActivatedEvent / DamageDealtEvent / HealAppliedEvent / UnitKilledEvent / CardDestroyedEvent / CollapseStartedEvent / CollapseDamageEvent / AnnihilationEvent / BattleEndEvent 等），经 CombatEventBus 分发。
- **完成标准**：`dotnet build` 通过；Resolver 配单元测试。

### 第 6 步：三层串联

#### 第 6 步子拆解（逐步讨论+执行）

- [ ] **6.1 GameManager 主状态机**：状态（选英雄 → 局内 → 结算）、`StartNewMatch` / `EndMatch` / `Surrender` / `ReturnToMainMenu`、`StateChangedEvent` 广播。
- [ ] **6.2 战斗触发链路**：遭遇点击 → 收集战场区卡牌 → `CombatManager.StartBattle` → 战斗运行 → 结束回传 `BattleResult`。
- [ ] **6.3 对局胜负判定**：10 次 PvP 胜利 → 对局胜利；声望 ≤ 0 → 对局失败；PvP 失败扣声望（= 当前轮次）、怪物战不掉声望；仅 PvP 后检查。
- [ ] **6.4 战斗结束回传结算**：奖励（财富 / 经验）、惩罚（声望）、应用永久变化到本体、`MatchEventBus` 事件联动。
- [ ] **6.5 对局内外分离校验**：战斗内事件不直发局外总线；对局层触发机制与战斗层触发机制独立。
- **完成标准**：对局闭环可运行。

- [ ] **7.4 卡牌展示**：卡牌信息展示（价值 / 等级 / 能力）、商店列表、购买 / 出售交互。
- **完成标准**：最小可玩版本。
