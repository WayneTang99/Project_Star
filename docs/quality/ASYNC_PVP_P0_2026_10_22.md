# 异步 PvP P0 首轮验证记录

日期：2026-10-22。首轮源码模式通过；后续官方专用导出、16项机制及进程通信探针也已通过，见第9节。P0 尚未全部完成，完整固定输入矩阵与正式网络／存档协议仍待验证。

## 1. 执行范围

新增独立入口 scripts/Presentation/Verification/ServerBaseline.tscn、ServerBaseline.cs 及 RunServerBaseline.ps1。入口不创建界面，不加载美术资源，不修改正式玩法或内容定义。复用 DefinitionRegistry、应用用例、CombatSimulator 和既有固定战斗基线。

云端程序与 SDK 位于 ubuntu 用户目录 ~/project-star-p0/，未创建正式玩家账号、存档、数据库、HTTP API 或系统服务。该目录仅是 P0 隔离验证工件，不作为以后玩家数据的默认目录。

## 3. 流程基线

以完整正式注册表组装现有 MatchPresenter，选择帕拉帝恩，普通回合优先选卡牌商店并购买一项可用商品。通过六次购买、第 4 回合怪物战、第 8 回合 PvP，进入第二轮第 1 回合。报告记录了本轮注册表计数，不能视作长期内容清单。

边界：此处复用当前试玩入口的固定种子 42、初始 999 金币和允许不足三项怪物候选的配置，对手仍是 LocalTestOpponentProvider。它证明现有 UI 流程／应用调用链可以走通，不证明正式经济平衡、严格排程全覆盖、真实玩家匹配或服务器权威存档已完成。P2/P3 必须将正式创建对局与试玩参数分开，不能直接把试玩入口作为服务端创建策略。

## 4. 确定性与编码

- 原有三组 CombatTraceChecks 固定基线通过。
- StringName 显式文本编码、ulong.MaxValue 字符串往返和 decimal=0.125 的诊断 JSON 往返通过。
- SeededRandom 保存状态后恢复，后续 20 次输出一致。
- 两组正式卡牌组合各预热一次、测量 20 次，重复结果诊断字节一致。
- Windows 与云端的两组诊断 SHA256 完全相同；最初本地 WSL 对照也一致，随后按用户要求停止使用 WSL，后续以云端验证为准。

| 场景 | 诊断 SHA256 |
|---|---|
| 初始等级正式卡牌组合 | 9AEEDB8C95FC4A8F86C607CF834E19841B72B3599E2FED780CDF341105779886 |
| 四级满盘组合 | 7C0773E30E38E3C22633987BDC37081C87E26D5E3CF9075756A4402382554B63 |

诊断投影包含结果、带类型的事件、数值状态、冷却、任务进度、元素／标签、召唤位置等，不包含所有能力定义或完整存档。它不是正式网络协议／完整回放序列化，不据两组输入宣称全部机制跨平台确定性已完成。构建模块 ID 单独记录，不作为规则指纹。

## 5. 云端测量

每组 20 次单线程调用 Simulate，分位采用排序后 nearest-rank（P95 为第 19 个样本）；不包含建立输入和 JSON 投影耗时。进程峰值包含注册、流程检查、模拟和诊断序列化；累计分配量不等于常驻内存。当前为 Debug 源码基准，尚非正式 Release 专用模板容量数据。

| 场景 | 单进程中位数 | 单进程 P95 | 事件／冻结状态数 | 诊断 JSON | 云端 gzip |
|---|---|---|---|---|---|
| 初始等级组合 | 92.31 ms | 147.36 ms | 68／836 | 2,049,849 B | 43,525 B |
| 四级满盘组合 | 670.81 ms | 694.94 ms | 416／1619 | 9,904,759 B | 266,402 B |

单进程全过程峰值约 377.6 MiB。满盘样本将双方英雄生命设置为 10000，以延长模拟、观察满盘成本；这是合成负载，不是对真实玩家典型战斗的统计或已证明的最坏场景。

另在云端同时启动两个独立验证进程，两者均成功退出，摘要与单进程一致：

| 进程 | 初始组合 P95 | 满盘组合 P95 | 各自全过程峰值 |
|---|---|---|---|
| A | 173.80 ms | 730.52 ms | 381.6 MiB |
| B | 153.12 ms | 710.11 ms | 355.2 MiB |

这只是两个独立 Godot 进程的短时对照，不是单进程线程安全测试，也没有 API、数据库、长时间积压或公网回放下载负载。不能据此设置正式战斗并发或承诺 500 人在线。

带宽结论：当前逐状态诊断投影未压缩体积较大，不能直接作为每次操作响应发送。正式回放格式需比较冻结输入＋客户端展示复算、事件／状态压缩等方案；其体积和客户端兼容必须单独验证。不同运行时的 gzip 字节数可不同，确定性比较使用未压缩规范投影。

## 6. 首轮未通过或未执行（后续复验见第9节）

- 正式专用模板导出未通过：缺少官方专用导出模板时，试用编辑器二进制作模板，启动要求 GodotSharp/Api/Debug 布局，与导出的运行数据目录不匹配并崩溃。已弃用该测试包；源码模式通过不代替此项，见 BUG-368。
- 云镜像缺少 libfontconfig.so.1，源码 headless 运行会输出动态库缺失提示，但本轮规则入口成功退出；部署依赖需要收口，见 BUG-369。
- 任务、宝石、升级、召唤／修复、全部状态联动等完整机制矩阵仍需补齐固定跨平台输入。
- 完整对局持久化、运行进程通信、正式账号、网络接口、真实对手池、500 人压测均未执行。
- 没有进行完整手工对局、全量规则回归、实际 UI 或原画验收。

## 7. 可复现入口

Windows／已配置 PowerShell 7 的主机：

```powershell
./scripts/Presentation/Verification/RunServerBaseline.ps1 -GodotPath '<Godot .NET 可执行文件完整路径>'
```

Linux 云端源码模式（需先由 dotnet build 完成构建，且设置对应 DOTNET_ROOT／PATH）：

```bash
godot --headless --path <隔离项目目录> \
  res://scripts/Presentation/Verification/ServerBaseline.tscn -- \
  --report=<诊断报告绝对路径>
```

入口成功返回 0，失败返回 1；包装脚本限制运行时间并检查 Godot ERROR。原始证据在本机 output/pvp-p0/ 的 windows.json、linux.json（早期 WSL）、cloud.json、cloud-concurrent-a.json、cloud-concurrent-b.json 及对应日志。cloud-build.log 为云构建证据。该目录被 Git／Godot 导入隔离，不作为持久玩家数据。

2026-10-22：已对官方 Godot 4.7.2 .NET 模板包完成 SHA512 校验，改用 linux_release.x86_64，云端补齐 libfontconfig1。BUG-368／369修复。新增机制检查曾因原画依赖失败，已将飞升者、钢制扳手、暗影斗篷的纯规则入口与原画检查分开；客户端原入口继续验证原画，云端16项纯规则通过，BUG-371修复。

当前通过的诊断程序在 /opt/project-star/releases/p0-20261022-174039-133/，root拥有、运行账号不可写；报告在 /var/log/project-star/p0/。未切换任何正式业务服务，也未创建玩家数据库／存档。更早失败的包只保留为诊断记录，不作为可用发布版本。

同一专用程序通过两帧 stdin/stdout JSON 诊断：同一进程接收两条不同key／seed／decimal输入并返回对应响应，退出码0。它验证进程边界编码，不是正式业务RPC、账号或存档协议。

最新官方专用包的16项检查覆盖任务阈值／永久成长／合并、来源摧毁、宝石效果／费用／刷新／升级、召唤占位／隔离、修复冷却／队列、隐身时长／伤害类型、元素联动、飞行与狂暴。两组诊断指纹与前述Windows相同。云端Release包首个复验样本P95约57／350ms、全过程峰值约291MiB；与此前Debug源码测量的构建、运行时及预热不同，不把差异完全归因于引擎模板。

另外新增 GitHub Release 流水线和共享 Bash 导出脚本。同一脚本的 server 分支已在云端 .NET 8 SDK 环境完成构建、导入、正式模板导出及冒烟运行；16项与2组指纹对照通过，原始JSON在 output/pvp-p0/ci-server-smoke.json。Windows客户端采用相同选项在本机原生官方编辑器实际导出，完整exe／pck／data_*生成且直接进程退出码0；日志 output/pvp-p0/client-export-direct.log。不表示已在GitHub触发Release或上传附件，说明见 [RELEASE_PIPELINE](../engineering/RELEASE_PIPELINE.md)。

当前不再以“缺官方模板／字体库”作为阻塞。仍需补齐全机制固定跨平台输入摘要、正式业务进程协议与存档边界；500人、实际账号与联网PvP仍未实施。本轮不宣称P0所有事项完成。
