# Project_Star UI 实施 Plan

日期：2026-09-30；更新：2026-10-01。状态：P0 契约与入口位置已确认，P1～P6 已实现并通过 Godot 自动回归；P6 已核对1280×720、1920×1080、2560×1440和2560×1080实际渲染图。P7完整人工验收仍待完成。

设计依据：[UI 系统设计](../design/UI_SYSTEM.md)。本计划细化 [总实施计划](IMPLEMENTATION_PLAN.md) 的第 10 步。**用户确认优先拆分架构、组件和数据刷新逻辑，再处理布局与视觉。**

布局以用户提供的右侧草图为准：顶部轮次，顶部右侧金钱/收入；下方三行共用三列边界，上排是场景头像、切换内容和离开按钮，中排中央为我方战场，下排为英雄头像、备战区、声望/经验/等级。中排两侧空白保留。详情使用浮层，上层切换商店/遭遇/敌方战场时不移动我方双棋盘。

## 1. 阶段顺序与交付物

| 阶段 | 交付目标 | 主要依赖 | 对应问题 |
|---|---|---|---|
| P0 | 固化职责、页面状态和数据契约 | 本次设计稿 | 阻止重复状态和不必要抽象 |
| P1 | 流程协调器、统一刷新、正确展示数据 | P0 | BUG-029/030/031/032 |
| P2 | 可独立渲染的组件与页面外壳 | P1 | 单脚本耦合、可见性遗漏、卡面复用 |
| P3 | 正确占格的棋盘及点击/拖拽预览 | P2 | BUG-028 |
| P4 | 完整构筑流程、交易与奖励界面 | P1～P3 | 商店文字卡面、出售入口、流程反馈 |
| P5 | 数据完整的确定性战斗播放 | P2、P4；先确认播放方案 | 现有日志不能完整还原 HUD |
| P6 | 统一主题、窗口适配和交互细节 | P3～P5 | 可读性、缩放、反馈一致性 |
| P7 | 完整对局回归与交付 | P1～P6 | 验证数据、界面与流程共同成立 |

优先完成的里程碑是 **P0～P2**：运行入口已拆分，组件只读渲染，一次操作驱动一次完整刷新。第二个里程碑是 **P3～P4**：卡牌占格、移动、交易、事件、奖励可完整操作。第三个里程碑是 **P5～P7**：战斗播放、统一视觉和最终验收。

这些阶段表示先后依赖，不是工期估计。未验收的任务保持未勾选；不以“代码已写”代替“已通过验收”。

- [x] P0-01 列出 `MinimalPlaytest` 当前方法到根节点、`MatchPresenter`、展示适配器、子视图的迁移表。
- [x] P0-02 定义页面状态及允许操作矩阵，覆盖英雄选择、遭遇、商店、事件、准备、播放、结算、对局结束；明确右上离开/继续与内容内开始战斗、购买、播放控制的区别。
- [x] P0-03 定义 UI 局部状态：选中实体、悬停实体、拖拽源/目标、详情、进行中的命令；明确重开、换页、实体移除时的清理规则。
- [x] P0-04 固化 `RefreshView` 的输入输出，以及 HUD、卡牌、棋盘、商品和详情真正需要的只读字段；标注现有字段与待增加字段。
- [x] P0-05 按用户草图绘制构筑、商店、战斗准备三张带尺寸的排版稿，核对 1920×1080 与 1280×720 的共同列宽/格宽；金钱/收入固定顶部右侧，补充技能/套装/奖励等未指定入口的设计，中排两侧暂不分配功能。
- [x] P0-06 把 BUG-028～032 对应的源码路径和人工复现步骤记入实施验收记录，保留当前已有的玩法验证基线。

**完成条件：** 每个数据字段和状态只有一个所有者；视图接口不接收可变领域对象；新的类或组件均有真实职责。P0 产物以接口和场景结构说明为主。

## 6. P4 — 构筑页面与交易闭环

- [x] P4-02 商店使用 `CardItemView` 显示商品，并独立显示购买价、购买按钮、合并提示、售罄和不可购原因。
- [x] P4-03 刷新费用与剩余可刷新状态由应用查询提供；过期商品点击不能操作新一批商品。
- [x] P4-04 将出售入口放在已选中卡牌的操作浮层，确认卡名、等级与当前回补价值后提交一次事务；原有出售奖励仍由应用用例处理。
- [x] P4-05 英雄与遭遇按实际条目数渲染；事件选项动态生成，反馈直接关联触发操作。
- [x] P4-06 奖励列表支持卡牌与技能，领取失败保留奖励；合并及自动放置成功后触发完整刷新。

- [x] P4-08 战斗结算/对局结束内容放在上排中央，下一步由右上离开区承载；日常操作反馈从大段日志改为局部提示，日志可展开查看。

**完成条件：**

- [ ] 金钱不足、满盘无法新增、满盘但可以合并、重复购买、不可刷新、过期点击均符合用例结果。
- [ ] 出售失败后卡牌与金钱保持原状；出售成功只移除一次、回补一次，并正确处理奖励。
- [ ] 同一卡牌在商品、棋盘、奖励和详情中的身份/等级/效果一致；报价与持有价值的差别有明确标签。
- [ ] 候选不足三个、长选项、无技能/套装、无奖励都有正常布局；从选角可完成一轮构筑与战斗准备。

| 类别 | 必测场景 | 通过标准 |
|---|---|---|
