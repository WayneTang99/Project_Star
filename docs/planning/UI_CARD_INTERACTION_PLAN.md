# 卡牌详情、直接获取与任务进度原型计划

日期：2026-10-10。状态：用户确认HTML排版后要求继续执行，下面四项项目接入已完成。详情去重、直接获取和任务进度区已在Godot中实施；正式玩法定义不变。完整HTML视觉对齐仍见专项待办。

## 本轮原型

- [x] 单一详情：保留卡牌右侧的详情面板，悬停／右键固定共用同一个容器；切换卡牌替换内容，关闭／Escape清理状态。右侧空间不足时仅移动这一个面板，不额外弹出第二份详情。
- [x] 直接获取：商品卡左键／Enter／Space直接购买，奖励卡直接获取；价格或“点击获取”作为提示，不要求点击独立按钮。棋盘卡左键仍固定详情。右键仅查看／固定，不触发交易。
- [x] 状态反馈：显示价格、余额不足、备战空间不足、已购买／已获取；重复点击不重复扣款或获取，失败保留卡牌。添加独立奖励预览入口。
- [x] 任务独立区：普通词条只保留发动／回响等规则；任务以独立的“成长任务”区显示条件、当前／目标次数、进度条、奖励、已解锁状态，不能只依靠颜色区分。
- [x] 登神者任务演示：沿用正式定义的20／60／120次目标与奖励，用示例进度0／35／75／120切换展示；不把示例进度写入正式内容，不增加领取任务奖励按钮，保持达标自动解锁语义。
- [x] 检查1280×720／1920×1080与615×440窄窗口、蓝色配色，验证详情只有一个、直接购买／获取、失败／重复门控、关闭／Escape、任务进度和正文滚动；保存代表截图。

原型检查证据：右键查看保持34金币；卡牌Enter购买后金币26、备战5/10，奖励左键／Space获取后金币保持26、备战分别7/10和10/10；空间不足保持卡牌和余额。20金币与12金币商品连续购买后余额2、备战9/10，再买8金币商品提示余额不足且不扣款。任务0／35／75／120次分别显示0／1／2／3项解锁，始终一个详情；关闭与Escape正常。窄窗口正文可滚动、无横向溢出，浏览器无错误。提交版外部资源页面已通过加载检查。

## 已实施的项目计划

1. **去重详情（BUG-141）**：核对`CardItemView._MakeCustomTooltip`和`MatchShell.ShowHoverCard`两条显示路径，保留右侧`CardDetailsView`，禁用卡牌的第二套引擎悬停窗；不关闭其他控件的必要提示。覆盖悬停等待、左右切换、固定后再悬停、刷新、关闭和Escape，始终只有一份详情。
2. **按场景分发卡牌点击**：商品／奖励的左键和键盘提交现有购买／获取命令，棋盘点击维持选择／移动行为；右键仅详情。复用原报价批次、奖励版本、禁用原因、合并条件和应用服务校验。拖拽松手不同时触发购买／获取；不更改正式交易规则。
3. **投影任务信息**：从正式任务定义读取目标和奖励，从实例／回放快照读取进度和解锁状态，通过只读ViewModel关联任务key；不能按展示文本解析规则。任务说明移入独立区，保留完整奖励语义和长说明滚动；任务在备战可累计、战场生效等规则不变。
4. **验收**：确认快照刷新、战斗／非战斗进度、0／中间／达标／超额／多任务状态、商品失败／售罄／奖励重复、键盘、拖拽与窗口缩放。构建、相关回归及实际截图通过后更新权威UI规范；完整HTML对齐仍按专项计划验收。

完成证据：构建0警告0错误，236/236回归、四档窗口／焦点／键盘和原生拖拽／出售通过。原生右键不交易、鼠标／Enter购买及Space奖励获取通过；1280×720、1920×1080、615×440分别捕获任务0／35／75／120、蓝色、滚动和商品悬停，完整奖励可读，只有一个详情。窄窗商品聚焦后自动横向滚动；关闭／Escape与刷新保留检查通过。代表截图及限制见[试玩验收](../quality/MANUAL_ACCEPTANCE.md)，BUG-141及本轮发现的BUG-145～152已修复登记。
