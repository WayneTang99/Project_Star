# UI 系统规范

本文描述当前已实施的界面边界与卡面规范。玩法见 [游戏规则](GAME_DESIGN.md)，业务实现见 [架构](../engineering/ARCHITECTURE.md)，待办见 [当前计划](../planning/IMPLEMENTATION_PLAN.md)，验收见 [人工验收](../quality/MANUAL_ACCEPTANCE.md)。历史迁移方案由 Git 保存。

2026-10-10 HTML迁移已恢复执行，完整视觉验收仍未完成；未完成差异与执行顺序见 [专项待办](../planning/UI_HTML_PARITY_TODO.md)。本文记录已接入的组件行为，不表示全部页面已与HTML一致。

## 数据流与所有权

玩家输入 → MatchPresenter → 应用用例 → Result / Snapshot → MatchPageViewModel → MatchShell.Render。

| 所有者 | 职责与生命周期 |
|---|---|
| `MinimalPlaytest` | 组装服务、资源与控件，连接和释放订阅；渲染帧只推进播放游标 |
| `MatchPresenter` | 当前页面、对局引用、商店/事件访问句柄、批次版本、操作门控与反馈；通过应用层读写业务 |
| `MatchPageViewModel` | 同一次刷新取得的只读身份、数值、操作条件与失败原因；不传可变 Session |
| `MatchShell` / 子视图 | 排版、控件、焦点、提示、浮层与输入意图；Render 不执行用例 |
| `BattlePlaybackPresenter` | 播放游标、暂停、1×/2×和反馈；只消费冻结的战前身份、事件与状态快照 |

战斗召唤物由冻结记录投影为临时卡面及战场放置，包含名称、等级、词条、属性与召唤反馈；战前画面尚无召唤物，播放到召唤后出现。回放不向对局库存或棋盘写入，战后正常快照不包含召唤物。

领域对象拥有金钱、棋盘、卡牌、奖励和对局进度。Presenter 持有访问句柄，不复制一份可变业务数据。技能、套装和奖励列表使用英雄详情浮层；结算页同时展示待领图卡并复用同一领取入口，任务使用卡牌详情，不增加对局流程状态。

操作成功或失败后统一刷新，HUD、棋盘、详情、商品与按钮来自同一批快照。预览、鼠标移动和 Resize 只改变表现状态，不重抽商品、不推进随机、不执行交易。实体失效、换页、重开和退出时清除过期选择、提示、拖拽与播放，释放订阅；动态按钮替换前解除旧连接。

## 页面与操作

| 页面 | 上层内容 | 允许的主要操作 |
|---|---|---|
| 英雄选择 | 已注册英雄 | 选择英雄创建新局；双棋盘隐藏 |
| 卡牌图鉴（局外） | 全部正式卡牌及支持等级 | 搜索卡名、标签或效果，按归属、尺寸、元素、初始等级筛选与排序，选择卡牌与预览等级；返回选角 |
| 技能图鉴（局外） | 全部正式技能及方形图标原画 | 搜索技能名或效果，按归属、初始等级筛选，切换支持等级；返回选角 |
| 遭遇选择 | 实际候选组 | 选择遭遇、调整构筑；不跳过未选择回合 |
| 商店 | 商品卡面、报价、售罄与刷新费用 | 购买、刷新、出售、离开；拒绝旧报价批次 |
| 普通事件 | 动态选项、成本与结果 | 成功执行一次后继续；失败保留上下文 |
| 战斗准备 | 敌方英雄与棋盘 | 调整构筑、开始战斗；空战场允许开始 |
| 战斗播放 | 冻结阵容与战斗数值 | 暂停、倍速、跳过；业务操作和棋盘修改被门控 |
| 战斗结算 | 结果、资源差额、允许领取的奖励 | 查看、领奖、继续；对局进行中可调整棋盘 |
| 对局结束 | 胜负与累计结果 | 返回选角、领取用例允许的末局奖励；棋盘只读 |

按钮状态不能代替服务校验。出售意图携带对局身份、卡牌、等级与金额，提交前重新核对；奖励索引结合列表版本，失败保留待领项。购买/合并/放置与从棋盘出售都是应用层完整事务。

遭遇选择使用横向原画图卡，整张图卡支持鼠标和键盘选择，底部浅色区域显示名称与一句用途简述；悬停及焦点显示描边。事件页面在内容区左侧显示原画、右侧显示动态选项及其效果说明，离开时隐藏。简述来自正式 Definition，选项说明由通用效果与当前英雄等级生成。原画资源与等级来自只读快照，渲染不重抽候选。图卡左上角及阶段标题显示等级晶体，复用卡牌晶体配色：1银灰、2蓝、3紫、4橙、5红；图卡同时显示等级文字，悬停说明商品等级上限。

普通事件与怪物图卡同样显示等级晶体及等级文字，分别读取可选项遭遇定义等级和怪物定义等级；进入后阶段标题保留该遭遇晶体。商店等级继续用于商品上限，其他遭遇等级不套用商店规则。

导师遭遇复用普通事件页面，显示本次最多三个技能的名称、授予等级和能力说明，完整说明可通过悬停读取。候选来自导师访问的冻结快照；刷新和重绘不重新抽选，成功选择后技能侧栏同步更新并允许继续。空池显示没有可传授技能并允许继续。导师遭遇等级同时决定本次导师及授予技能等级，测试入口的等级覆盖遵循同一关系。

`Playtest.tscn` 测试入口统一把商店、事件、怪物战及 PvP 遭遇设为4级，图卡和阶段标题使用橙色晶体。覆盖值由入口注入应用排程，写入候选快照；商店生成与刷新按候选中的4级上限处理，刷新费用8金币。正式 Definition 和普通排程仍使用原等级；商品使用定义初始等级，怪物卡组保留原配置；显式随遭遇等级发放的奖励使用本次4级访问等级。

## 布局与输入

英雄选择页右上角分别提供卡牌图鉴与技能图鉴入口，打开任一图鉴时隐藏选角和两个入口，返回或Escape恢复选角并把焦点移回对应入口；进入对局后隐藏入口。技能图鉴复用局外浏览布局：左侧可滚动的方形原画列表，右侧原画预览、等级选择和可滚动的完整技能说明。默认显示初始等级，只列出定义支持的等级，切换后效果数值来自该等级能力快照；不赋予技能卡牌的尺寸、元素、价值或宝石孔。搜索匹配技能名、归属和各等级效果，与归属和初始等级筛选组合；空结果隐藏旧详情，筛选和返回不获得技能或执行能力。

`SkillCatalogQuery`捕获正式目录并生成只读条目，由入口注入`SkillCatalogView`，新增正式技能自动进入图鉴。`SkillItemView`从`SkillSnapshot.Illustration`加载方形图标，图鉴及已获得技能详情共用；缺图夹具使用占位图，效果关键词复用详情配色。

选角页采用左侧英雄名册、中央完整方形原画、右侧身份和初始属性的三列布局。名册显示头像、姓名和称号，选中项以天蓝描边及勾选标记强调；点击名册或方向键切换只更新本地预览，原画使用150毫秒轻过渡。右侧称号与姓名分开显示，初始属性可折叠，数值来自Definition投影的只读`HeroSelectionDetails`，不在视图硬编码。确认按钮固定在右侧底部，显示“以姓名开始冒险”；点击确认或Enter才通过既有用例创建对局，图鉴等外部控件持有焦点时不会抢占按键。刷新按key保留当前浏览英雄，名册内容未变时复用按钮与焦点，替换后解绑旧按钮。布局按可用宽高收敛，宽屏内容居中，名册超出高度时纵向滚动。选角期间隐藏棋盘和英雄侧栏，展示区域占满顶部栏下方；进入对局后恢复英雄侧栏与右侧三段内容。英雄插画来自只读身份与快照，缺图时仍可选角并显示姓名。

圣骑士选角原画使用8秒循环待机：上身每4秒随呼吸起伏，头颈整体轻摆，持锤手与整把锤同步移动，发梢、披风与衣摆延迟摆动。现有原画通过轮廓蒙版进行局部形变，面部不参与布料波动，背景建筑与方形边界保持稳定。锤头和胸前圣徽叠加呼吸圣光、柔和光晕与短光芒，光源跟随人物位移；少量金色光点缓慢上浮，光效避开面部与原画边界。同页刷新保留播放进度，打开图鉴或隐藏选角页时暂停，返回继续；切换至圣骑士时从头播放。动效仅用于中央选角原画，名册与对局头像仍显示静态原画。

圣骑士选角配音为中文男声“圣光引领着我们！”。点击名册中的圣骑士或方向键切换到他时播放，重复点选从头重播，单个播放器避免叠加；初始展示和只读刷新不自动触发。切至其他英雄、清空名册、打开图鉴、隐藏选角页或退出时停播；返回选角页后再次主动点选才播放。音频使用随项目打包的本地资源，游戏运行时无需语音生成服务。

新增英雄默认同时生成并接入原画，维护规则见 [内容数据规范](CONTENT_DATA.md#英雄)。英雄原画使用方形构图，面部保持清晰以适应选角预览与侧栏头像；图片本身不包含文字、卡框或UI。

选角页右上角提供“卡牌图鉴”。打开后覆盖局外内容，左侧为可滚动的全卡列表，右侧独立预览卡面、等级与完整说明；卡面保持小/中/大型比例。第一行搜索匹配卡名、归属、标签及词条效果并显示结果数量；第二行提供归属、尺寸、元素、初始等级四个筛选条件及排序字段、升降序按钮。筛选与搜索取交集，默认四项均为全部；双元素卡包含所选元素即可匹配，初始等级按正式Definition判断，不受详情预览等级影响。排序可选上述四个维度：归属按菜单顺序，尺寸按小、中、大，元素按通用、火、水、风、土、雷、木、冰、光、暗，双元素再比较第二元素，初始等级按数值；同组按卡牌key稳定排列。刷新保留仍在结果中的卡牌及预览等级，关闭再打开保留筛选和排序条件；空结果隐藏旧详情。详情等级仅列出正式定义支持的等级，默认显示初始等级；切换后同步更新卡面、基础数值、冷却、魔法消耗及价值。效果描述直接读取正式词条，不推算任务解锁后的身份或对局加成。列表与说明分别滚动，效果关键词复用现有配色。返回按钮或Escape恢复原先浏览的英雄，关闭后键盘焦点回到图鉴入口；进入对局隐藏图鉴入口。

图鉴由入口调用`CardCatalogQuery.Capture`，把正式目录投影为只读条目与等级快照后注入`CardCatalogView`。查询不创建实体、执行拾取/出售/任务效果或推进随机；新增正式卡牌自动进入目录。皮肤与动效尚未实现，后续接入独立预览区，玩法定义继续作为数值和词条来源。

可选项遭遇的加权结算结果在确认前显示各分支概率，说明从通用效果生成并使用本次访问等级；植物奖励同时注明尺寸。加权说明每行组合最多两个结果，多行按钮使用13px字号，使小窗仍能同时显示奖励与怪物风险。进入怪物分支后使用既有战斗准备、回放和结算页面；无符合当前轮次且同等级的怪物时显示提示并允许继续旅程。

卡面以底边中央的菱形逐个显示宝石孔：金色描边与深色凹槽表示空孔，明亮宝石渐变填充表示已镶嵌，多个孔横向居中排列，零孔隐藏。卡面不显示孔字、数量文字或宝石名称；悬停提示和详情逐孔列出空孔、宝石名称及说明。等级由整张卡框颜色表示。商店报价显示定义孔数及空孔，棋盘与回放读取卡牌冻结快照；本阶段不提供尚未定义渠道的镶嵌按钮。

顶部左侧轮次，中间八回合轨迹标记当前访问回合，第4/8回合带怪物战/玩家对战图标及说明，右侧图标显示金币/收入。访问商店、事件、战斗准备/回放/结算时保留进入前的轮回合，返回遭遇选择后才展示领域已推进的下一回合，避免访问第1回合商店却标成第2回合；下方英雄侧栏固定在左，右侧三段共用同一内容宽度：

| 区域 | 内容 |
|---|---|
| 英雄侧栏 | 肖像、姓名、称号与等级、生命/魔法、技能/套装/奖励入口；底部经验、声望与胜场 |
| 右侧阶段区 | 标题、等级晶体与阶段操作；敌方战场 / 遭遇 / 商店 / 事件 / 结果互斥切换 |
| 右侧中排 | 战场，10格 |
| 右侧下排 | 备战，10格 |

生命、魔法、经验使用语义图标和数值资源条，经验为当前经验／10，悬停可读资源名称。声望、胜场、护甲、灼伤和中毒使用图标配数字。构筑阶段生命显示当前上限、魔法显示初始魔法，回放阶段生命和魔法使用冻结战斗快照同步更新；敌方标题下同步显示生命、魔法、护甲。回放反馈在侧栏底部显示最近两行，悬停可读完整文本，不覆盖经验与等级。

阶段内容切换不移动我方双棋盘。最低窗口1280×720，同时覆盖1920×1080、2560×1440和2560×1080以及缩回小窗。对局主区按 HTML 最大宽度1400及水平内边距居中，阶段、战场、备战和底部英雄栏自然纵向排布，超出窗口时通过`DesktopScroll`滚动，不为塞进720高而压缩整个棋盘。棋盘格间距6px、内部边距10px，格高为格宽的两倍，多格卡跨越相应格间距；拖拽使用同一`SlotPitch`映射。浮层限制在视口内。`MatchTheme`提供森林金／星辉蓝表现切换、渐变面板、背景光和低对比星形；精确材质仍待对照验收。禁用状态保留原因说明。

对局主题的中文使用 Microsoft YaHei 常规字重，品牌和关键数值使用 Georgia，按角色设置字号、字重与字距。HTML 提取的 SVG 图标和渐变位于`art/ui/html/`。对局视口关闭HDR 2D，使半透明UI按与浏览器一致的sRGB方式合成；截图读回不再额外做线性转sRGB。

商店商品横向排列，同高卡面显示等级和元素，右侧信息区显示卡名、冷却与价格按钮，合并资格来自协调器的购买条件查询。购买按钮共用基线，售罄、失败原因及操作反馈保留；完整卡牌信息使用悬停和右键详情。阶段插画区显示等级文字、标题和说明，下方为刷新、离开及“•••”开发折叠入口；底部英雄区提供主要继续／开始操作。战斗摘要提供暂停、倍速、跳过及查看敌方阵容；展开后的返回入口尚待修复。

棋盘共用横向格位标尺，小/中/大型占1/2/3格；标题只显示区域名及已用/总格数，空格序号弱化显示在底部。`BoardZoneView`按EntityId复用独立`CardItemView`，卡面与外层点击区均覆盖完整占格区间，不留额外内缩缝隙。独立组件也同时按宽度和可用高度约束格宽，保持1:2/1:1/3:2比例；落点和预览使用实际格高。外层接收鼠标与拖拽，CardFace装饰忽略鼠标。

拖拽载荷只携带 MatchId、EntityId、抓取格偏移和占格数。预览调用只读 `PreviewPlaceCard`，原卡保持原位；提交重新计算完整 PlacementPlan。取消、失败、越界、只读区域和旧对局载荷均不改变模型。点击/键盘移动沿用相同应用入口。

## 战斗回放

`ResolveBattleForPlayback` 一次完成结算，返回双方战前身份、BattleResult 与玩家结算后快照。播放只消费 BattleResult.States 与原事件日志；同 Tick 保持记录顺序，EventCount 指向日志前缀。治疗、护甲、魔法、状态衰减、冷却、充能和摧毁都读取真实记录，不由 UI 补算。

自然结束或跳过只切换到结算页，不重复发奖；暂停、倍速不改变结果。战前身份使永久摧毁的卡牌仍能完成回放。强调 Tween 只影响装饰，重复强调先停止旧 Tween，换页与退出释放。

## 卡面与详情

CardFace 只读取 CardFaceViewModel，显示身份、等级、插画、元素、效果和价值；详情、标签和冷却显示在外层。商店、棋盘、奖励共用卡面和 CardDisplayAdapter。插画缺失时显示统一占位并保留真实身份。

### 固定版式

以高度 400 为基准，各尺寸维持同高：

| 尺寸 | 卡面宽 × 高 | 比例 |
|---|---:|---:|
| 小型 | 200 × 400 | 1:2 |
| 中型 | 400 × 400 | 1:1 |
| 大型 | 600 × 400 | 3:2 |

- 卡面隐藏卡名，不设置通栏标题与底栏；卡名由悬停和详情读取。整张卡框使用等级颜色（1银灰、2蓝、3紫、4橙、5红），不显示左上等级菱形或卡面等级文字。底边菱形仅表示宝石孔，多个孔居中并排，零孔隐藏。
- 底图：原画覆盖卡牌宽高的100%，等比填满并按整张卡牌裁切；不同尺寸和效果数量不再改变插画区域。不拉伸原画。
- 所有信息和边框都作为overlay叠加在插画上；2px等级色外框及同色65%透明度的1px内描边包围5px内缩插画，底部遮罩改善数值可读性。效果格使用对应语义颜色的渐变，数值使用 Georgia；价值牌渐变仍待对齐。
- 属性圆徽23px贴右上角，距右边和上边7px；双属性以4px间隔并排，通用属性用银灰圆徽。宝石孔由8px正方形旋转45°形成菱形，正方形间距7px，整组在底边中央排列；650px及以下视口使用6px正方形与5px间距。
- 底部左侧：效果图标与数值按传入顺序纵向堆叠，每项独立格子，行高25px、间距3px、底边留7px。数值默认15px，窄视口13px；宽度用实际字体测量。只显示卡面容纳的前几项，完整规则与公式由详情承载；极小商品的长数值边界仍待验收。
- 底部右侧：价值图标和当前价值放在左边斜切的独立区域，靠右下对齐；与左侧效果格留出间隔。
- 不显示冷却、描述、标签等其他字段。

外框由等级决定，桌面配色和归属不覆盖等级色。字体与布局对所有卡牌相同；不改变信息位置、字号、徽章大小或整张卡牌的插画覆盖范围。悬停轮廓使用等级色，选中和键盘焦点轮廓向外绘制以保留等级框。基准卡面、紧凑棋盘、商店与奖励共用同一规则。

新增卡牌时传入该卡的尺寸、等级、归属、原画、属性、效果数值和当前价值，然后调用 `CardFace.SetCard(viewModel)`；不复制卡框或重写排版。英雄变化只需传入不同 `FactionKey`，原画资源由卡牌自身提供。

### 可查看场景

`CardFaceShowcase.tscn` 使用正式臂铠、野猪、审判之锤定义，分别展示小型、中型、大型卡。当前全部正式卡牌均有独立生成的原画。

原画生成与更新使用项目 Skill `project-star-card-artwork`（`.codex/skills/project-star-card-artwork/SKILL.md`）。当前采用细致明亮的手绘日式奇幻画风；生成前读取卡牌 Definition 的尺寸，分别按小型1:2、中型1:1、大型3:2构图，并核对输出实际比例。2026-10-03更新的17张旧原画已符合此比例；此前补齐的9张原画暂用方形，后续按对应尺寸调整。2026-10-04补齐7张缺失原画，小型887×1774，中型1254×1254，均符合对应比例；当前正式卡牌不再使用占位图。

插画属于卡牌属性集的只读身份字段 `CardIdentityAttributes.Illustration`，由对应卡牌 Definition 声明。对局快照和商店报价快照传递该字段，`CardDisplayAdapter` 按路径加载并缓存纹理，再交给卡面显示；不维护按卡牌 key 匹配图片的列表。插画为空或资源不存在时使用共用占位图，组件展示中的缺图示例只覆盖展示快照。

示例价值从项目 `CardValueCalculator` 读取。效果数值只作为展示输入，不由卡面 UI 计算战斗结果。

卡牌详情读取 `CardSnapshot.DescriptionEntries`，正式条目由卡牌只读身份 `CardIdentityAttributes.DescriptionEntries` 提供。按有序列表逐条显示“词条名称：说明”，名称由 `CardKeywords` 统一维护，包含发动、回响、光环、拾取、出售、任务、消耗和被动；当前等级、价值和实例基础/当前数值另列。紧凑卡面仍只显示关键图标/数值，完整描述留在详情中，不覆盖整幅插画。

悬停与固定卡牌详情共用`CardDetailsContent`：标签／20px卡名／49px冷却圆徽、12px规则正文、等级／元素／价值底栏。浮层通常330px宽，窄视口290px；正文按实际换行后的高度排版，达到窗口允许上限后滚动。宝石、实例属性及任务相关信息通过底部展开入口读取；固定选择保留明确的出售确认。`CardDetailsView`按内容最小高度及时收缩，关闭按钮独立定位于右上方并释放固定状态；相邻定位不足时翻转，最后限制在视口内。

详情标题使用Microsoft YaHei粗体及2px字距，圆徽数值使用Georgia粗体，正文行高22.2px并突出关键词和数值；标签先显示尺寸，再显示其余标签及元素。背景按实际面板尺寸绘制130°渐变，蓝色桌面仍保留HTML详情的配色。正文与展开区共用窗口高度预算；同卡刷新只更新快照，保持位置、淡入进度及展开状态；固定详情在页面滚动／缩放时保持可见，失效卡牌及换页仍关闭。

详情的基础／当前属性按实际能力用途展示：只有具备发动能力才显示冷却，伤害效果读取攻击属性时才显示攻击。不能仅按数值是否为0判断，真实攻击为0仍需显示；辅助卡牌的占位攻击、无发动能力的冷却不显示。

飞行／狂暴由布尔战斗快照提供，为真时出现在卡牌战斗状态和详情中，为假时不显示；不显示层数，也不将它们混入攻击等数值属性。回放按记录刷新并保留旧快照，非战斗默认无这些状态。

战斗卡牌不显示剩余CD数字，底栏上缘使用3px天蓝冷却进度线，随剩余冷却减少从左向右填充，发动后重置，不遮挡原画和关键数值。比例读取战斗快照的剩余冷却和实际完整时长，包含冷却倍率与战斗增时；多发动能力取最大剩余比例。无冷却、备战、摧毁和非战斗卡牌不显示进度线，状态文字与交互轮廓保持可见。

非战斗且棋盘可编辑时，己方战场／备战卡牌可拖至顶部信息栏和上方商店／遭遇区域出售。该区域只在有效己方卡牌拖拽时显示出售提示，悬停查询现值回补，松开直接出售并结算出售效果。Escape取消或释放到目标之外不出售；敌方卡牌、旧对局载荷、战斗回放及终局不可出售。提交时再次校验等级、金额和出售条件，失败保留卡牌及资源；原详情确认出售入口保留。

详情及卡牌悬停提示中的关键词按下表着色；正文和数值保持默认颜色，原始描述不添加富文本标记。表现层使用颜色栈渲染字面文本。
