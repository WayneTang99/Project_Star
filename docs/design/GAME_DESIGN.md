# GAME_DESIGN.md

Project_Star 游戏设计规则。本文档记录游戏侧的设计需求，与 `AGENTS.md`（导航）、`docs/engineering/ARCHITECTURE.md`（架构实现）配合使用；术语定义见 `docs/design/GLOSSARY.md`。

## 一、核心要素

- **英雄（Hero）**：玩家选择的角色，携带属性集，是构筑与战斗的主体。
- **卡牌（Card）**：构成角色构筑与战斗手段的核心资源，可通过商店交易获得。
- **技能（Skill）**：独立于卡牌的能力载体，不占棋盘格；首版只提供被动能力，可由任意内容入口获得。
- **遭遇（Encounter）**：玩家回合中的选项（商店/怪物战/PvP），可能为单遭遇或多选一。与领域事件（Match Event / Combat Event）区分。

## 二、游戏流程

- 玩家**选择英雄**进入游戏。
- 游戏以 **轮（Round）** + **回合（Turn）** 逐步递进，每回合可能出现各种遭遇。
- **商店遭遇**中，玩家可以**交易卡牌**。购买的卡牌优先自动进入战场区；战场区放不下时进入备战区；两区都放不下时不能购买。
- 玩家没有独立库存区域，只拥有**备战区（Bench）** 与 **战场区（Battlefield）**，并可随时在两区之间调整卡牌。
- **默认回合**为**三选一遭遇组**，其中**至少 1 个商店遭遇**。
- **每轮第 4 回合**：3 个怪物遭遇，三选一挑一个进入战斗。
- **8 回合为 1 轮**，每轮**最后一回合（第 8 回合）固定为异步玩家对战遭遇**。
- 同一候选组不重复；候选进入列表时即记为已出现，未出现遭遇抽取权重 ×2。
- 普通候选池不足 3 个时返回全部可用候选，不复制遭遇凑数。
- 可选项遭遇可以声明任意数量的选项、固定或加权随机的展示槽及通用效果；随机结果由对局随机状态确定，表现层按定义动态生成选项，不为具体遭遇硬编码按钮或结算逻辑。
- 玩家对战遭遇与怪物遭遇点击后**进入战斗**，战斗使用**战场区卡牌**自动进行。

## 三、对局胜负

- **对局胜利** = 第 8 回合 PvP 胜利累计满 **10 次**。
- **对局失败** = **声望 ≤ 0**。
- 声望只在 **PvP 战斗结束后**检查；PvP 失败扣声望，扣量 = **当前轮次**；怪物战不掉声望。
- 战斗胜利 ≠ 对局胜利：战斗胜利只是该场战斗结果；战斗内英雄血量归零仅为该场战斗失败，不影响对局。

## 四、遭遇排程

- 按当前轮过滤可排布遭遇模板：`MinRound <= 当前轮 <= MaxRound`。
- **未出现加成**：遭遇有基础权重（默认 1）；本局尚未出现的遭遇权重乘固定倍率提高排布几率，已出现遭遇回落基础权重。
- 按遭遇 key 跟踪本局已出现遭遇，新对局时清空。
- 怪物是独立的预设战斗内容，定义固定战斗属性与卡组，不作为玩家可选英雄。
- 怪物定义等级、固定卡牌和技能。怪物战结束后无论胜负，按怪物损失生命比例分别获得 `⌊(怪物等级+2) × 损失生命 ÷ 最大生命⌋` 金钱和 `⌊(怪物等级+1) × 损失生命 ÷ 最大生命⌋` 经验；经验先累计，不触发未定义的英雄升级规则。
- 怪物战胜利时，从怪物携带的每张卡牌和每个技能实例中等概率抽取一件，加入待领取奖励；同名的多个实例分别占一个抽取位置。奖励按怪物携带等级领取，卡牌沿用获得折半与自动放置、合并规则，技能沿用技能获得与合并规则。卡牌放不下时奖励保持待领取。
- 野猪使用默认战斗属性，固定拥有两张彼此独立的1级兽皮，分别放置在战场第1、2格；另有一张1级中型野猪卡，放置在第3～4格。
- 正式怪物定义会自动进入试玩怪物候选并按固定卡组创建对手；内容扩充期的试玩模式会展示当前已有怪物，不要求先凑满三个定义。
- 体能训练是普通可选项遭遇：选择“强化体魄”永久增加当前英雄等级 ×10 的最大生命；选择“耐力训练”永久增加当前英雄等级 ×1 的生命再生。
- 垃圾填埋场是1级普通可选项遭遇，每次展示两个选项：固定展示“获得2金币”；另一个选项按60%概率提供本职业随机一张1级小型卡牌、按40%概率提供随机一张1级小型材料卡牌。卡牌奖励自动放入战场区或备战区的首个可用位置；两区都无法容纳时选项仍正常结算，但不生成卡牌。

## 五、英雄系统

- 当前英雄定义：帕拉帝恩（内部 key：`hero.paladin`，卡牌归属 key：`paladin`）。
- **继承定义**：每个英雄是 `HeroDefinition` 的子类，构造函数内声明身份字段（key/展示名/阵营）和初始属性差异；**不建英雄场景**（逻辑层纯代码）。
- **定义注册**：用反射扫描程序集收集所有非抽象英雄定义子类；玩家选择时由实体工厂从定义创建独立实例（含独立属性集）。
- **商店与卡牌**：英雄不管理商店。卡牌定义携带**归属 key**；一般商店默认按当前英雄归属 key 提供其专属卡牌。
- **型号商店**：小型商店、中型商店、大型商店只刷新当前英雄归属下对应尺寸的卡牌；无阵营卡和其他英雄归属卡不进入这三类商店的商品池。
- **商店等级**：小型商店和中型商店为1级，大型商店为2级。商店等级是商店自身配置；在另行定义等级效果前，不改变商品卡牌的生成等级。
- **商店商品与刷新**：商店从符合归属与型号的卡池中无重复展示最多3件商品；卡池不足3件时展示全部且不可刷新。卡池超过3件时每次商店可付费刷新1次，1～4级商店刷新费用依次为2 / 4 / 6 / 8金钱；余额不足时不扣款且商品不变。
- **归属不限制使用**：英雄可以获得并使用其他英雄归属的卡牌；跨英雄卡牌可以通过特殊商店、遭遇、奖励等来源获得。
- **无阵营卡牌**：使用统一 `neutral` 归属 key，不专属于任何英雄，可由面向所有英雄的内容池提供。
- **英雄不使用标签**：标签是卡牌分类；`Human` / `Mechanical` 等标签只挂载于卡牌，不挂载于英雄定义或实例。

## 六、卡牌系统

### 身份字段

卡牌有不可变的身份字段（创建后不可修改）：
- **CardKey**：唯一标识
- **DisplayName**：展示名
- **FactionKey**：内容归属 key（所属英雄/阵营或 `neutral`），用于卡池筛选，不限制其他英雄使用
- **Size**：型号尺寸（Small/Medium/Large）
- **ElementKeys**：元素属性 key 集合；每张卡牌必须拥有 1～2 个不重复属性，顺序不影响含义

### 元素属性

- 可选属性：`General` / `Fire` / `Water` / `Wind` / `Earth` / `Lightning` / `Wood` / `Ice` / `Light` / `Dark`。
- `General` 对应无属性，是十种属性之一，不表示空值或缺省状态。
- 每张卡牌至少 1 个、最多 2 个属性。
- 同一张卡牌不能重复持有相同属性。
- 双属性不区分主次和顺序。
- 元素属性属于只读身份字段，卡牌实例创建后不可修改。
- 当前阶段只用于分类、筛选和能力条件，不引入属性克制规则。

### 可变属性

- **Level**：等级
- **Value**：价值
- **PersistentBonus**：对局内加成
- **UnlockRecord**：解锁记录（对局内按 key 跟踪）

### 等级配置

- 卡牌定义可以为不同等级提供独立的基础数值与能力参数，并声明获得时的初始等级。
- 普通等级范围为 1～4；定义不必提供全部普通等级，例如内容可以从 3 级开始。
- 内容需求只写“X级”时，默认表示初始等级为 X 且支持 X～4级；明确写“5级”时表示固定5级特殊内容。
- 第 5 级是可选内容配置，不是所有卡牌都有；只能通过特殊获得途径直接创建，不能由同级合并产生。
- 未提供某等级配置的卡牌不能以该等级创建。
- 获得同 key、同等级且低于4级的卡牌时，优先合并升级已有实例；允许连续合并，目标按 `EntityId` 稳定选择，任何合并都不能产生5级。
- 合并升级保留目标实例 ID、棋盘位置、当前价值和 Modifier，并按新等级刷新基础战斗值与能力；只有实际创建新实例时才需要棋盘空间。
- 百分比伤害使用整数确定性计算，小数部分向下取整；未声明无视护甲时按普通伤害先扣护甲。
- 按己方英雄当前生命百分比缩放的卡牌伤害，在每次发动结算时读取己方英雄当前生命与最大生命；伤害 = 基础攻击 × 当前生命 ÷ 最大生命，小数部分向下取整。
- 对卡牌战斗属性的数值修改只作用于本身具备对应属性能力的卡牌；不会为缺少该能力的卡牌凭空赋予能力。例如“攻击 +10”不使无攻击能力的卡牌获得攻击能力。
- **多重 N**：多重是卡牌的可变战斗属性。一次正常发动后按当前多重值额外发动 N 次；额外发动完整执行该能力的全部效果，但整组发动只进入一次冷却。
- **魔法消耗范围**：只有主动能力（发动）会检查并消耗魔法；魔法不足时不发动。回响与被动光环不消耗魔法。
- **被动光环**：仅在来源卡牌位于战场区且未被摧毁时持续生效；来源被摧毁后立即失效；多个同类来源按 Apply 规则累加。

### 价值公式

默认初始价值 = **价值系数 × 等级倍率 × 型号系数**。

- 普通卡价值系数为 2，型号系数为小 1 / 中 2 / 大 3
- 等级倍率为 1级 `1` / 2级 `2` / 3级 `4` / 4级 `8` / 5级 `8`
- 默认初始价值表：小型 2 / 4 / 8 / 16 / 16，中型 4 / 8 / 16 / 32 / 32，大型 6 / 12 / 24 / 48 / 48
- 卡牌等级配置可以显式覆写该等级的初始价值；未覆写时使用通用公式
- 等级变化**不**自动重算价值，增值/减值事件直接修改价值

### 获得折半

**任何途径**加入玩家卡池即视为获得（购买、掉落、奖励一致），价值统一按 `初始价值 × 0.5` 折半；购买按初始价值全额计价。折半与购买行为无关，目的是让后续增值/减值事件的**叠加逻辑**始终作用在一致的半价基线上；出售按现值**全额**回补，不再二次打折。

卡牌等级配置可以声明通用的获得时自身价值加成，在折半后累加。兽皮 1～4 级分别获得 `+2 / +4 / +8 / +16` 价值，因此获得后的当前价值为 `3 / 6 / 12 / 24`。

### 获得与放置

- 购买和奖励属于待领取内容，必须由玩家点击获取。
- 点击获取成功后仍按战场区优先、备战区其次自动放置；两区均无空间时获取失败，购买不得扣款，奖励保持未领取。
- 出售触发、事件即时生成等自动获得不等待点击，立即按战场区优先、备战区其次放置。
- 自动获得时两区均无空间则不创建卡牌；触发该奖励的原操作仍正常完成。
- 随机获得使用对局随机状态，并在筛选候选后按稳定 key 顺序抽取，保证相同状态得到相同结果。

### 英雄收入

- 英雄收入默认值为5，属于可被 Modifier 调整的对局属性。
- 创建对局时结算第1轮收入；以后每次进入新轮时，在生成该轮遭遇前结算一次。
- 同一轮重复调用收入结算不会重复发放，并产生 `IncomeGrantedEvent` 供表现层与验证使用。
- 珠宝袋初始为2级，支持升级到3级和4级；出售后从支持其当前等级的材料卡中随机自动获得一张。若两区已满，出售和金钱回补照常完成，只跳过材料卡奖励。

### 定义注册与实例化

系统用反射收集所有非抽象 `CardDefinition` 子类；实体工厂据此创建独立卡牌实例，商店按归属 key 过滤定义。

### 技能规则

- 技能定义与实例分离；技能归属使用与卡牌相同的阵营 key，`neutral` 表示无阵营；已获得技能保存在当前对局中，新对局重新建立。
- 技能不进入卡牌库存、战场区或备战区；战斗时作为所属方的独立被动能力来源。
- 技能沿用卡牌的同 key、同等级合并规则：普通等级最高合成至4级，5级只能直接获得；升级保留实例 ID，并按目标等级刷新数值与能力。
- 首版技能不能配置主动能力，也不能配置要求来源必须是卡牌的自身效果。
- 战斗开始触发的被动能力在 0 tick 结算一次，先于首个冷却或状态结算；多个来源按稳定顺序处理。
- 正式技能“突袭”无阵营，初始1级；战斗开始时对敌方英雄造成其最大生命值 5%／10%／15%／20% 的普通伤害（分别对应1～4级，小数向下取整，先扣护甲）。

### 套装规则

- 每张卡牌最多属于一个套装，套装 key 是卡牌只读身份数据。仅战场区卡牌参与套装计数；相同卡牌 key 的多个实例只计一次。
- 卡牌描述所表达的效果、技能、套装阈值解锁和任务解锁均由可复用能力组合实现；描述文本本身不另建规则执行路径。
- 达到的各个阈值效果累计生效。效果默认仅作用于战场区的本套装卡牌；特殊目标由效果描述明确指定。效果写“全部卡牌”时仅作用于战场区，不包括备战区。
- 每条非数值效果的持续时间由该效果描述明确指定，不设统一持续时间。
- 棋盘变化后重算非战斗套装效果，并精确移除失效阈值的贡献；战斗开始时固定套装快照，随后即使卡牌被摧毁，本场已生效的套装效果仍保持有效。

## 七、标签系统

- **标签容器**：轻量级通用标签容器（`HashSet<StringName>`），无元数据，只存 key。
- **标签常量**：定义所有游戏标签（`Small`/`Medium`/`Large`/`Equipment`/`Material`/`Human`/`Beast`/`Mechanical`/`Demon`/`Undead`/`Consumable`/`Location`）。
- **显示名映射**：返回中文显示名（如 `Equipment` → `"装备"`），未知标签返回原始 key。
- **标签由卡牌挂载**：如型号标签（由尺寸自动推导）+ 词条标签。

## 八、棋盘与推挤系统

### 双棋盘

玩家拥有**备战区（Bench）** 与 **战场区（Battlefield）**，各 10 格。

- 成功获取的卡牌必须立即放入棋盘，不存在游离于双棋盘之外的已获取卡牌。
- 自动放置顺序固定为：战场区优先，备战区其次。
- 两区均无可用空间时，本次购买不可执行，也不扣除财富。

### 推挤规则

- 目标区间无阻挡 → 直接放置
- 有阻挡 → 任一块不可推挤直接失败；否则分别模拟向右/向左，择优执行

### 择优

先释放被拖卡牌原位；方向按 距离短 → 影响卡牌少 → 取 Right。

## 九、能力系统（游戏侧）

### 核心模型

- **能力（Ability）**：可被触发的动作单元。主动（冷却/手动）与被动（事件触发）都是能力，区别仅在于触发方式。能力只负责执行逻辑。
- **效果（Effect）**：被能力触发的被动后果（静态修饰 / 周期 DoT-HoT）。

### 能力复用约定（重要）

- ⚠️ **能力必须可复用，禁止为单张卡写专属能力**：能力是通用动作单元，一张卡由多个已有能力组合而成。
- **卡牌组合能力**：卡牌定义中组装已有能力、目标选择和效果，通过参数差异化。
- **禁止具体卡牌引用**：卡牌能力不得引用另一张具体卡牌的 key、定义类型或实例类型。卡牌间联动必须通过元素属性、标签、位置、战斗属性或领域事件等通用条件表达，确保能力可以被其他卡牌复用。
- **新能力的判断标准**：只有当现有能力组合无法表达所需逻辑时，才新建能力类。新能力必须能被多张卡复用。
- **禁止的情况**：如 `FrostSwordAbility`（仅服务于“寒霜短剑”一张卡）→ 应拆分为攻击 + 迟缓组合。
- **正确示例**：`寒霜短剑` = 攻击能力 + 迟缓能力（时长 1s）；`迟缓术` = 迟缓能力（时长 3s）；`重击` = 攻击能力（伤害 50）。
- **等级伤害由卡牌处理**：能力不感知等级。卡牌根据等级设置属性值，并在等级变化时自动更新。能力只读属性，不关心值从哪来。

### 效果堆叠约定

适用于所有可叠加属性（时长、中毒、灼伤、生命再生等）：

- **Apply 累加**：效果的施加必须**累加**到目标属性，而非覆盖赋值。多个来源对同一目标施加同类效果时，属性自然叠加。
- **到期扣减**（有时长效果）：效果到期时从目标属性中**扣减该实例贡献的量**，而非直接清零。
- **不清零**：有时长效果的移除不再直接设置属性为 0，属性由衰减逻辑自然归零。
- **抵消判定**：根据属性最终值判断倍率（疾速×2 / 迟缓×0.5 / 两者均>0时抵消×1），与效果实例数量无关。
- **回响截断**：非回响事件可以触发回响；回响执行产生的事件不得再触发其他回响，不形成回响链。
- **灼伤**：每 1 秒造成当前值的护甲优先伤害，每 0.2 秒减少 1；同 Tick 先伤害后衰减。
- **中毒**：每 1 秒造成当前值的无视护甲伤害，伤害后向下减半。

## 十、战斗时间规则

- 战斗有 A/B 超时（A 正常对局超时 / B PvP 对局超时），超时自动结束。
- 战斗时间阶段用语见 `docs/design/GLOSSARY.md`「战斗描述用语」。
