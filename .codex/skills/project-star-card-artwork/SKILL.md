# Project Star 卡牌原画

为当前项目生成或更新卡牌原画。先读取 AGENTS.md、docs/design/UI_SYSTEM.md 与目标 scripts/Content/Cards/ Definition，确认名称、主体、尺寸、元素、标签及现有插画路径；不从卡名猜尺寸。

## 比例与构图

| Definition 尺寸 | 卡面比例 | 生成构图 |
|---|---|---|
| Small | 1:2 | 竖向，建议1024×2048 |
| Medium | 1:1 | 方形，建议1024×1024 |
| Large | 3:2 | 横向，建议1536×1024 |

实际卡面规则以 UI_SYSTEM.md 为准。像素大小可因工具能力调整，宽高比必须符合卡牌尺寸。生成后读取图片实际宽高，不能只凭提示词或缩略图声称符合比例。比例不符时用图像生成工具重新构图，不拉伸、不用加边或代码裁切冒充符合尺寸。

原画覆盖整张卡面，名称、等级、元素、效果与价值由游戏叠加。图片本身不生成文字、卡框、UI、标志或水印。**主体性优先**：主体在缩小后的卡面上仍应清楚、醒目，背景和装饰服务主体；不为追求全身、完整翼尖或完整武器而缩小主体，允许边缘部分出画，但关键装备、轮廓和职业识别须清楚。顶部和底部降低细节密度以适应信息遮挡。人物保持适合尺寸的姿态；长武器按宽高比调整方向，不能把所有主体机械放进方形画布。

**非英雄人物的面部处理**：人物卡牌尽量不呈现鲜明、可辨认的个体脸部特征，优先用头盔、面罩、兜帽阴影、闭眼、发光眼或圣光/魔法效果弱化面部识别。根据人物身份选择自然的处理方式，不强制所有人都戴同一种装备；通过装备、动作、轮廓和职业效果突出主体，不用精细脸部肖像承担卡牌辨识。英雄原画保留角色面貌，不套用此规则；动物、植物和物品不因本规则被遮脸。

**细长物品的完整形制**：战矛、法杖、扫帚等以物品本身为主体时，应看清整体形制及主要两端，不做只剩矛头、杖头等局部的特写。用斜向构图、适度透视、主体与背景的明暗分离及简化背景兼顾完整与醒目，不能用极端裁切代替主体突出。此要求不强制人物全身或巨龙翼尖完整入画。

在主体突出的基础上，尽量让画面有张力：按内容选择动作、视角、斜向构图、前后层次或光影对比，不强求所有物品都做夸张动作，不用过量特效和拥挤背景抢夺注意力。

## 画风与参考

用户当前认可的是细致明亮的手绘日式奇幻：细线条、丰富材质、柔和绘画阴影和自然色彩，人物为精致动漫比例。不要默认沿用早期粗描边Q版原画。

**职业一致性与区分**：同一职业的线条、人物比例、材质、光照和渲染细致程度不要差距过大，并保持可识别的主色调；不同职业尽量有明显色调区分。生成前查看同归属的已认可卡牌及英雄原画，优先以其建立风格和色调基准。元素色、单卡情绪可作局部变化，不应让所有职业都套用圣骑士的金色暖光。无阵营卡牌按主体采用自然色彩，不强行归入某个职业。尚无稳定职业基准时说明建议，不把一次临时配色写成已获认可的固定色板。

**圣骑士军团配色**：以白色＋金色建立主色调和军团识别，不要求整幅或所有材质都变成白金。钢铁、皮革、动物与环境保留自然色；按身份、装备、旗帜功能或效果，在合适位置使用少量红、蓝、紫及其他辅助色，形成层次和单卡差别。避免大面积绿色衣料和旗面继续成为军团主配色；不能把此要求扩大成禁止一切其他颜色。破誓者等特殊身份保留必要暗色和局部效果色，同职业统一不等于每张卡同样配色。

参考图从当前正式Definition的Illustration读取，不按旧文件名或历史文档选择已弃用版本。圣骑士可查看随军牧师与盾甲士当前原画，物品可查看小型魔法药水当前原画，均位于 art/ui/card-face/artwork/。前两者用于圣骑士绘画品质，药水用于玻璃材质与物品细节；它们不自动成为尺寸、构图或职业色调的合格模板，仍须按现行规则核对。跨职业参考只借鉴绘画品质，色调以目标职业为准。先查看参考的实际图像；用户指定的新风格优先于这些候选。避免把参考角色、盾牌、营地等主体误搬到其他卡牌。

更新已有原画时：查看旧图和风格参考，旧图用于保持主体身份，风格参考用于线条、光照和材质；输入图片的角色必须在提示词中明确。允许按目标卡牌比例重新构图。缺图新建时根据 Definition 的主体与玩法编写图像规格，使用当前内置工具允许的参考机制，不臆造不受支持的尺寸或路径参数。

## 生成、检查和接入

1. 使用 imagegen Skill 与内置 image_gen，一张卡一次调用，多个主体不拼成图集。只有用户明确选择时才使用CLI/API替代路径。
2. 提示词注明目标卡、主体、参考角色、精确宽高比、主体优先的构图、张力处理、职业风格与主色调，以及禁用文字/UI要求。批量开始前确认范围；用户说全部时从当前正式 Definition 查出全部目标。
3. 每张生成成功立即记录卡牌key、来源文件、提示词和目标路径，保存进项目，避免中断后失去已完成结果。中断恢复先核对图片及 Definition，不盲目重生成。
4. 查看输出及缩小后的卡面，检查主体是否突出、画面张力、非英雄人物是否弱化个体脸部特征、同职业风格一致性及跨职业色调区分，再检查解剖与装备、实际比例、文字与边框、卡面遮挡风险。主体边缘出画本身不是缺陷；只有影响识别或卡面可读性时才修正。需要修正时只调整具体问题，继续使用图像生成工具。
5. 正式文件存入 art/ui/card-face/artwork/。更新旧图时优先保存独立版本并切换对应 Definition 的 Illustration，方便对比；不删除旧图或共享占位图。新增图不能只留在 Codex 生成目录。
6. 仅修改目标卡牌的 Illustration 路径，不改变身份、数值或机制。引用使用 res:// 项目路径，不引用 ref/。Godot自行生成导入文件，不手工制造缓存。
7. 原画纹理必须生成 mipmap：新增或替换后检查对应 `.import` 的 `mipmaps/generate=true`、`mipmaps/limit=-1`，通过 Godot 重新导入生效，不直接修改 `.godot/` 缓存。卡面及预览使用 `LinearWithMipmaps` 采样；验收同时核对实际加载纹理 `GetImage().HasMipmaps()`／层数，并查看图鉴紧凑卡面与放大预览，检查缩小后的锯齿、颗粒和细节闪烁。不能仅凭导入配置已写 true 就宣称生效；HTML预览不能替代Godot采样验证。
8. 交付列出补齐/更新数量、实际尺寸和保存路径，报告检查结果；运行游戏验证或其他测试须遵循当前会话授权。提示词记录可放 output/，不建立额外正式内容表。

新卡若经用户明确允许临时使用其他比例，交付说明该例外，不将临时例外变成今后默认规则。
